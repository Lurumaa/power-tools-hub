# Canvas-саби і переходи в Power Tools Hub: формат, рантайм, перевірка, експорт

Документ для розробників, які вбудовують це в Kaleido. Робочий прототип — основний Power Tools Hub
(`skillhub/index.html`, артефакт https://claude.ai/artifact/6A2gzYgdr9Kk1Heeu58ShH). Рушій Canvas прийшов із Lab-копії
(`skillhub_canvas/`, 2026-10-23, до репозиторію не входить) і злитий в основний хаб; Lab більше не джерело правди.

## 1. Суть

Стиль субтитрів — це один JSON. Крім назви, шрифтів і повзунків у ньому лежить **код малювання одного кадру**.
Платформа нічого не знає про конкретний стиль: вона дає коду час, слова з таймінгами й розмір кадру, а код
сам малює що завгодно (лава, хмари, маркер, частинки). Так само влаштовані переходи в хабі (поле `shader` з GLSL),
тільки тут JavaScript + Canvas 2D.

Тому новий стиль = новий JSON. Міняти платформу під стиль не треба; будь-який Claude пише такий JSON за шаблоном
(`CANVAS_TEMPLATE.md`, кнопка **Copy template** у хабі), людина вставляє його в хаб і одразу бачить прев'ю.

Наші «рідні» рушії (`editor`, `word`, `coach`, `motion`) лишаються як є: це параметри поверх готових анімацій.
Усі п'ять рушіїв рендеряться у відео нашими скриптами локально (Claude склеює сам): `editor`, `word`, `coach` — свої
скрипти, `motion` і `canvas` — `podcast/tools/hub_subs.py`, який запускає власний код хаба кадр за кадром (§7).

## 2. Формат пресета

```json
{
 "name": "lava-wave",
 "title": "Lava Wave",
 "engine": "canvas",
 "runtime": 1,
 "description": "Одне речення: як виглядає і коли використовувати.",
 "fonts": ["Montserrat:900"],
 "params": [
  { "name": "size",  "label": "Text size",        "min": 0.5, "max": 1.2,  "value": 0.72 },
  { "name": "y",     "label": "Height on screen", "min": 0.3, "max": 0.85, "value": 0.5 },
  { "name": "color", "label": "Lava colour", "type": "color", "value": "#ff6a00" }
 ],
 "code": ["const P = s.phraseAt(s.t, { maxWords: 3 });", "if (!P) return;", "..."]
}
```

| Поле | Що це |
|---|---|
| `name` | id для чату й бази: латиниця в нижньому регістрі, цифри, дефіси, до 64 символів (`use subs lava-wave`) |
| `title` | назва на картці, до 60 символів |
| `engine` | завжди `"canvas"` |
| `runtime` | версія API `s` (див. §4), під яку написано код. Зараз `1` |
| `fonts` | Google Fonts: `"Family"` або `"Family:400,800"`, курсив `"800i"`, до 6 штук |
| `params` | базові повзунки (до 8, зайві відкидаються з попередженням): число `{name,label,min,max,value[,step]}` або колір `{name,label,type:"color",value:"#rrggbb"}`. `name` — слово для коду (`^[a-z][A-Za-z0-9_]{0,30}$`, до 31 символу), `label` — до 40 символів |
| `code` | тіло функції `function (ctx, s) { ... }`. Масив рядків (зручно читати й порівнювати в diff) або один рядок — платформа склеює через `\n`. До 60 000 символів |

Де лежить: база артефакту, `sublib/<name>` (бібліотека власника) і `subs/<uid>/items/<name>` (у кожного автора своє).
Формат статично перевіряє `validatePreset()` (гілка `canvas`), під час публікації — ще й прогоном (§6).

## 3. Контракт виконання

- Платформа на кожен кадр викликає `code(ctx, s)`.
- `ctx` — `CanvasRenderingContext2D`, уже відмасштабований у координати кадру `s.W × s.H`, очищений, **прозорий**.
  Код малює лише саби; відео лежить знизу.
- **Формат:** саби — лише **9:16 (1080×1920)**: прев'ю в хабі (сітка, вікно пресета, редактор) і перевірка під час публікації
  йдуть лише в 9:16, перемикача формату в сабів немає. Рантайм сам приймає будь-який розмір кадру (`s.W`, `s.H`), і
  `hub_subs.py` на горизонтальному відео малює Canvas-стиль на 1920×1080 — такий кадр хаб не показує й не перевіряє.
  Код однаково не має зашивати 1080/1920: розкладка від `s.W`, `s.H`, `s.safe`, довжини × `Math.min(s.W, s.H) / 1080`.
- **Детермінізм:** картинка залежить лише від `s.t` (+ слова, розмір, повзунки). Час може стрибати назад
  (прев'ю зациклене, експорт іде кадр за кадром). Жодних `Math.random()`/`Date` — для цього є `s.rand`/`s.noise`.
  Стан між кадрами — лише кеші в `s.memo` (скидається під час зміни тексту, розміру кадру чи повзунка, після
  завантаження шрифтів і на початку перевірки).
- **Пісочниця:** у коду немає мережі, DOM платформи, картинок. Лише Canvas 2D (шляхи, градієнти, текст, `ctx.filter`,
  `getImageData`/`putImageData` на службових шарах).
- **Швидкість:** перевірка під час публікації міряє код на полотні 640 px по довгій стороні (живе прев'ю — за розміром вікна
  × devicePixelRatio, до 3): потрібні одиниці мс на кадр. Lava Wave: ~3 мс на 640 px; на повному 1080×1920 у headless
  Chromium без GPU ~30 мс JS (~95 мс із відмальовуванням браузером, замір `tools/preview.py` 2026-10-23).

## 4. API `s` (runtime 1)

| | |
|---|---|
| `s.t` | час кадру, с |
| `s.W`, `s.H` | розмір кадру: у хабі завжди 1080×1920 (9:16); `hub_subs.py` бере розмір за формою відео (1080×1920 або 1920×1080); рантайм приймає будь-який |
| `s.safe` | `{x0,y0,x1,y1}` — безпечна зона: з боків `0.065·W`, згори `0.1·H`, знизу `0.17·H` для вертикалі (H/W > 1.5), інакше `0.08·H` |
| `s.params` | значення повзунків за `name` (читати із запасним значенням) |
| `s.words` | `[{text, start, end}]` — слова з таймінгами (с від початку ролика), текст як сказаний, із пунктуацією |
| `s.total` | довжина ролика, с |
| `s.phrases(opt)` | розбивка слів на екранні фрази `[{a,b,idx,start,end,from,to}]`; `opt = {maxWords:6, maxChars:30, maxDur:2.8, gap:0.35, lead:0.1, hold:0.4}`; ріже за кінцем речення і паузами ≥ gap; фраза на екрані з `from` до `to` |
| `s.phraseAt(t, opt)` | фраза на екрані в момент t або `null` |
| `s.wordAt(t)` | індекс слова, що звучить (останнє з `start <= t`), `-1` до першого |
| `s.prog(t,t0,dur)`, `s.clamp`, `s.lerp` | прогрес 0..1, обмеження, інтерполяція |
| `s.ease.*`, `s.bezier(x1,y1,x2,y2)` | linear, in/out/inOut Quad/Cubic, outQuart, outExpo, inOutSine, outBack; CSS cubic-bezier |
| `s.measure(text, font)` | ширина тексту, px |
| `s.layer(id)` | очищений offscreen-шар у тих самих координатах |
| `s.blit(layer, {alpha, blur, color, blend})` | накласти шар (blur у px, color — тонування, blend — `globalCompositeOperation`) |
| `s.glow(fn, opts)` | намалювати фігури в шар, затонувати, розмити, накласти |
| `s.noise(x, seed)`, `s.rand(n)` | гладкий шум −1..1, детерміноване «випадкове» 0..1 |
| `s.k` | масштаб «піксель кадру → піксель пристрою» |
| `s.memo` | кеш між кадрами |

Реалізація — функція `canvasRuntime()` у `skillhub/index.html`, без залежностей.

**Версії.** Додавати в `s` нове можна в межах runtime 1. Якщо щось змінюється несумісно, це runtime 2,
а платформа тримає прошарок для пресетів із `"runtime": 1`. Хаб попереджає, якщо пресет написано під новішу версію,
ніж він уміє.

## 5. Як це працює в хабі (прев'ю)

1. Для кожної картки / вікна прев'ю створюється `<iframe sandbox="allow-scripts" srcdoc=...>` — непрозорий origin:
   код пресета не має доступу до хаба, його бази та акаунта глядача. **Ізоляція за процесами залежить від браузера.**
   Chrome на десктопі (і застосунок Claude) виносить sandbox-iframe в окремий від хаба процес, але **всі** прев'ю
   хаба ділять один такий процес: пресет, що завис, на цей час зупиняє решту canvas-прев'ю і перевірку.
   Тому в хабі є сторож (`canvasFreeze`, `CW`): якщо прев'ю не відповіло 2.5 с, хаб знімає всі canvas-прев'ю
   (це гасить процес, що завис), через 4 с повертає їх по одному на «випробувальний термін» — кожне пробігає весь
   ролик кроками 0.1 с. Прев'ю, яке зависає саме, лишається вимкненим із написом «The code stopped answering
   (a loop that never ends?). Preview stopped.» до зміни коду; те, що не стартувало за 6 с, — «The code did not start. Preview
   stopped.»; те, що шле понад 400 повідомлень за секунду, — «The code floods the page with messages. Preview stopped.».
   Без такої ізоляції (Safari, Firefox, headless
   Chromium за замовчуванням) код, що завис, підвішує всю сторінку. **У Kaleido:** виконувати код пресета у Worker
   (OffscreenCanvas) або в окремому процесі з лімітом часу на кадр, а в сітці не крутити чужий код усім підряд
   (постер-кадр, живе прев'ю — лише у відкритого пресета).
2. Прев'ю перебудовує iframe лише тоді, коли код чи шрифти справді змінилися: знімок коду береться під час
   оновлення прев'ю (із затримкою 0.35 с після введення), а не на кожен кадр. Сітка сабів не перестворює картки під час
   пошуку й фільтрів — лише ховає (перебудова iframe = перезавантаження й блимання). Під відкритим вікном пресета чи
   редактором картки сітки не анімуються.
3. `srcdoc` = `<link>` на Google Fonts + рантайм (`canvasRuntime`) + `window.__draw = function (ctx, s) { <code> }`
   (`canvasDoc()`).
4. Батьківська сторінка шле `postMessage`:
   - `{hubCanvasIn: 1, words, total, W, H, params}` — на старті й під час зміни тексту / розміру кадру / повзунків;
   - `{hubCanvasIn: 1, t, seq}` — на кожен кадр;
   - `{hubCanvasIn: 1, check: {...}}` — прогін перевірки (§6).
   Відповіді: `{hubCanvas: 1, alive: 1, seq}` не частіше разу на 200 мс після малювання (для сторожа).
5. Iframe відповідає `{hubCanvas: 1, ready: 1}`, `{hubCanvas: 1, err: "..."}` (помилки коду показуються на прев'ю)
   і `{hubCanvas: 1, check: {...}}` (лише числа, пікселі назовні не йдуть).
6. Тло (темне, світле або будь-який тон між ними повзунком, свій кадр) малює батьківська сторінка під прозорим iframe.
7. **Формат.** Саби — лише 9:16: сітка, вікно пресета й редактор завжди показують кадр 1080×1920
   (`setViewFmt(view, '9:16')`), перемикача формату в сабів немає. Перемикач 9:16 / 16:9 (`fmtPicker`) є лише
   в переходів — у вікні переходу і в редакторі: вікно лишається 9:16, кадр 16:9 грає смугою по центру, зони згори та
   знизу вкриті світлою напівпрозорою сіро-зеленою вуаллю поверх тла (`FMT_VEIL = rgba(143,160,150,0.18)`,
   `fmtFrame()`), без ліній по краях смуги. Вибір запам'ятовується в глядача (`localStorage hub.fmt`, поле `trans`; поле
   `sub`, якщо трапиться, — залишок, хаб його не читає). Сітка карток завжди вертикальна.

## 6. Перевірка під час публікації

**Canvas-саби** (`runCanvasCheck()` + `runCheck()` у рантаймі). Поки код/шрифти/повзунки в редакторі змінюються,
хаб (через 0.45 с після останньої зміни) піднімає окремий прихований sandbox-iframe і проганяє код на тестовому
тексті: 48 кадрів по всьому ролику в 9:16 (1080×1920), полотно 640 px по довгій стороні (360×640), між кадрами — віддача керування
потоку (MessageChannel), пікселі аналізуються на копії в 1/4 розміру. Кнопка Publish неактивна, поки немає результату
(у підвалі «Checking the code on test frames…»).
Значення повзунків знімаються один раз на старті прогону; результат приймається, лише якщо підпис
(код + шрифти + повзунки) збігається з поточним.

Протокол: хаб шле `{hubCanvasIn: 1, check: {id, words, total, params, size: 640, frames: 48, formats: [[1080,1920]]}}`
(рантайм уміє прогнати й кілька форматів, хаб шле один — 9:16), рантайм відповідає `{hubCanvas: 1, check: {checkId, formats: [{W, H, n, errors, errorFrames, speaking, emptySpeaking,
edgeFrames, belowFrames, nondet, avgMs, p95Ms, maxMs}], fatal?}}`.

| Блокує публікацію | Попередження |
|---|---|
| код не завантажився (синтаксис) | у середньому понад 12 мс/кадр або 95-й перцентиль понад 25 мс — «heavy» |
| виняток хоча б в одному кадрі | порожні кадри, поки звучить слово (не більше половини таких кадрів) |
| немає відповіді за 10 с — зависання | суцільна заливка (альфа > 128) біля краю кадру в 10%+ кадрів (обрізано?) |
| порожньо більш ніж у половині кадрів, де звучить слово | 9:16: заливка в нижній смузі під кнопками застосунку в 10%+ кадрів |
| 50+ мс/кадр у середньому на 640 px або один кадр довше 1 с | кадр, намальований повторно поза чергою, відрізняється (стан між кадрами) |

«Порожній» кадр — менше 3 пікселів з альфою > 10 на копії 1/4 (≈ 48 на 640 px). Порівняння «повторно поза чергою» йде
по сітці 24×24 середніх (альфа × яскравість) з допуском 4 рівні — різниця округлення розмиття GPU/CPU не рахується,
`Math.random()` і лічильники в `s.memo` ловляться. Перевірка — фільтр якості, не межа довіри: код пресета живе в
тому самому вікні, що й рантайм перевірки, і теоретично може підробити відповідь; довіряти йому однаково не можна (§8).

**Переходи** (`transCheck()`). На спільному WebGL2-контексті, на тестових кадрах 90×160 і 160×90: за progress 0
шейдер мусить показати A, за 1 — B (допуск 6 рівнів у максимумі, 0.6 в середньому) — інакше Publish заблоковано;
якщо середина (0.25/0.5/0.75) повністю чорна — попередження (NaN). Результат кешується за шейдером, налаштуваннями і
довжиною; у редакторі перевірка запускається через 0.3 с після останнього руху повзунка (не на кожен крок), одразу —
за «Compile and play». Усі 10 переходів бібліотеки проходять; негативні тести (суміш 50/50, чорна середина,
синтаксис) ловляться.

## 7. Експорт у відео

Прев'ю в хабі — це живий браузер поверх тестового тла. У рекламі саби мають бути **впечатані в кадри mp4**.
Оскільки код — детермінована функція часу, експорт простий:

```
для кадру n = 0 .. N-1:
    t = n / fps
    очистити полотно W×H (прозоре), викликати code(ctx, s) з s.t = t
    взяти RGBA кадру  ->  накласти поверх кадру n відео  (або зібрати в потік з альфою)
```

**Уже працює локально:** `podcast/tools/hub_subs.py --style <preset.json> --words <words.json> --video <in.mp4> --out <out.mp4>`
(`--param name=value`, `--offset`, `--preview N`, `--timeout` — за замовчуванням 30 с, до першого кадру 4×). Скрипт шукає хаб
за відносним шляхом `../../skillhub/` (`index.html` і `tools/build_page.js`), тому `podcast/` і `skillhub/` мають
лежати поруч (як у репозиторії). Motion: сторінка хаба на localhost у headless Chromium, `attachView` + `drawSubFrame` на
прозорому полотні 1080×1920 (лише 9:16; горизонтальне відео — відмова). Canvas: та сама сторінка `build_page.js`, що в
`tools/preview.py` (iframe sandbox + CSP), кадр 1080×1920 (на горизонтальному відео скрипт технічно малює 1920×1080 —
хаб такий кадр не показує й не перевіряє). Огородження браузера слабше, ніж у preview.py: Playwright-route пропускає
`file:`, `data:` і URL, де трапляється fonts.googleapis.com / fonts.gstatic.com; немає DNS-правила, заборони UDP у WebRTC
та OS-пісочниці Chromium; браузер — у дочірньому процесі, якщо немає прогресу `--timeout` секунд — дерево процесів убивається
`taskkill /T` (не job object). Кадри RGBA одразу йдуть у ffmpeg і накладаються на відео, звук копіюється, NVENC ~5 Мбіт/с
(без NVENC — libx264 crf 18). Швидкість: Motion ~20 кадрів/с, Lava Wave ~3.5 кадра/с (ролик 30 с ≈ 4–5 хв). Розробникам Kaleido
це потрібно, лише якщо рендер буде на їхньому сервері.

Варіанти:
- **Сервер:** headless Chromium (Playwright/Puppeteer) вантажить той самий `srcdoc` на нативному W×H, на кожен кадр робить
  знімок із прозорим тлом (або віддає `getImageData`), ffmpeg накладає на відео / збирає ProRes 4444,
  VP9-alpha або PNG-послідовність.
- **У браузері користувача:** той самий рантайм на `OffscreenCanvas` + WebCodecs.

Робочий прототип покадрового рендера — `skillhub/tools/preview.py` + `build_page.js`: той самий рантайм (береться прямо
з `skillhub/index.html`), той самий код, рендер по кадрах у 9:16 з будь-якими значеннями повзунків (`--fmt 16:9` лишився для
експериментів — хаб 16:9 у сабів не показує й не перевіряє):

```
python skillhub/tools/preview.py <preset.json> <out_dir> --param color=#00a8ff --param size=1.2 [--sheet-only] [--strip T0 T1 N] [--shots 1.2,3.4] [--timeout 20]
```

Прототип зроблено так, як має працювати експорт: код пресета живе в `<iframe sandbox="allow-scripts">` із CSP
(`default-src 'none'`, шрифти лише з Google Fonts) усередині хост-сторінки; мережу браузера закрито (Playwright route
пропускає лише саму сторінку і fonts.googleapis.com / fonts.gstatic.com, плюс DNS-правило й заборона UDP у WebRTC);
браузер працює в дочірньому процесі (на Windows — у job object), і якщо завантаження, шрифти чи один кадр не
просуваються `--timeout` секунд, усе дерево процесів убивається, а в `errors.txt` пишеться «the preset hangs or is far
too slow at t=…». Час на кадр друкується двома числами: JS-малювання (як у перевірці хаба) і повний цикл із
відмальовуванням браузером. CSP забороняє `eval`/`new Function` — такий пресет у прототипі впаде.

Що потрібно на вході експорту:
- **Слова з таймінгами** `[{text, start, end}]` від початку ролика. У нас їх дають Groq Whisper, ElevenLabs Scribe,
  точні початки слів — wav2vec2. Якість синхрону = якість цих таймінгів.
- **Шрифти** з `fonts` (завантажити з Google Fonts в оточення рендера).
- **fps і розмір кадру** ролика (`s.W`, `s.H`).
- Значення повзунків користувача.

Слова для `hub_subs.py` — файл `[[word, start, end], ...]` (або `[{text, start, end}]`). Свого вирівнювача в
репозиторії немає: підійде будь-який, що віддає такий список (наприклад, Whisper з word timestamps).

**Оточення локального рендера:** Python 3.11 + playwright (`python -m playwright install chromium`) + Pillow (preview.py)
+ numpy і moderngl (transitions.py); Node.js (build_page.js); ffmpeg і ffprobe у PATH; psutil — за бажанням (preview.py
добиває ним залишки процесів).

Переходи вже рендеряться у відео: `podcast/tools/transitions.py` — той самий GLSL у moderngl на GPU, будь-який розмір кадру.

## 8. Безпека

Код пресета — недовірений: опублікувати може будь-хто. Виконувати **лише ізольовано**:
- у браузері: iframe `sandbox="allow-scripts"` без `allow-same-origin` (так у хабі);
- на сервері: окремий процес браузера без доступу до внутрішніх сервісів, мережу закрито (крім шрифтів),
  **ліміт часу на кадр** і на весь рендер (пресет, що завис, не має тримати чергу) — як у `tools/preview.py`.
- у прев'ю хаба мережу обмежує CSP самої сторінки claude.ai (srcdoc-iframe її успадковує); локально (localhost)
  такого обмеження немає.

## 9. Шаблон для Claude і цикл якості

- `CANVAS_TEMPLATE.md` (і кнопка **Copy template** у хабі) — інструкція для будь-якого Claude без контексту: формат,
  API, правила, планка якості й робочий приклад (Lava Wave).
- Головний висновок тестів: наосліп за шаблоном виходить посередньо, сильно — коли дивляться кадри й правлять. Тому
  цикл завжди такий: Claude пише JSON → вставка → Apply → перевірка (§6) → дивитися прев'ю на темному / світлому тлі
  і на своєму кадрі (9:16) → зауваження назад Claude. Якщо Claude вміє запускати код, `tools/preview.py` дає йому кадри сам.

## 11. Відкриті питання

- Власні файли шрифтів (не Google) для Canvas-пресетів поки не підтримуються.
- Немає послівних позначок (ключове слово, акцент) — можна додати в `s.words[i]` у межах runtime 1 без поломок.
- `ctx.filter` (розмиття для світіння) — перевірити в Safari, у якому дивитиметься команда.

## 12. Розділи хаба і де лежать дані

Хаб — одна сторінка (`skillhub/index.html`, заголовок «Power Tools Hub»), чотири розділи: **Skills**, **Subtitles**,
**Transitions**, **Music** (`#skills`, `#subs`, `#trans`, `#music` або `#<name>` в адресі відкривають розділ / елемент).
Дані — у базі артефакту (capabilities `db`, `user`, `assets`, `downloads`):

| Розділ | Бібліотека власника | Своє в автора | Поля |
|---|---|---|---|
| Skills | `library/<name>` | `skills/<uid>/items/<name>` | name, category, description, files, binaries, video / videoLink, products, … |
| Subtitles | `sublib/<name>` | `subs/<uid>/items/<name>` | `PRESET_KEYS`; рушії editor / word / coach (Marker) / motion / canvas |
| Transitions | `translib/<name>` | `trans/<uid>/items/<name>` | `TR_KEYS`: name, title, description, duration (0.1–3 с, у редакторі 0.1–2), anchor 0–1, params, shader |
| Music | `musiclib/<name>` | `music/<uid>/items/<name>` | `MU_KEYS`: name, title, artist, source, rights, factory, moods, bpm, beat, drops (до 4), duration, lufs, peaks, asset (id аудіо в asset store, AAC у .mp4), note |

Документи `skills/<uid>`, `subs/<uid>`, `trans/<uid>`, `music/<uid>` (`{updatedAt}`) — індекс авторів: за ними хаб знаходить
чужі піддерева. Власник пише в бібліотеку (`library`, `sublib`, `translib`, `musiclib`), решта — у своє
піддерево; ім'я, зайняте іншим автором, опублікувати не можна. В елементів бібліотеки автором показується «Power Tools
Hub». На 2026-10-23 у бібліотеці: 1 скіл (stickman-talking), 12 документів сабів, 10 переходів, 12 треків; піддерева
авторів порожні. «Copy for Claude» у розділі Music містить адресу хаба (константа `HUB_URL` — адреса артефакту з початку
документа; аудіо завантажується через Artifact read) — під час перенесення в Kaleido замінити.
