# Canvas-сабы и переходы в Power Tools Hub: формат, рантайм, проверка, экспорт

Документ для разработчиков, которые встраивают это в Kaleido. Рабочий прототип — основной Power Tools Hub
(`skillhub/index.html`, артефакт https://claude.ai/artifact/6A2gzYgdr9Kk1Heeu58ShH). Движок Canvas пришёл из Lab-копии
(`skillhub_canvas/`, 2026-10-23) и смерджен в основной хаб; Lab больше не источник правды.

## 1. Суть

Стиль субтитров — это один JSON. Кроме названия, шрифтов и ползунков в нём лежит **код отрисовки одного кадра**.
Платформа ничего не знает про конкретный стиль: она даёт коду время, слова с таймингами и размер кадра, а код
сам рисует что угодно (лава, облака, маркер, частицы). Так же устроены переходы в хабе (поле `shader` с GLSL),
только здесь JavaScript + Canvas 2D.

Поэтому новый стиль = новый JSON. Менять платформу под стиль не нужно; любой Claude пишет такой JSON по шаблону
(`CANVAS_TEMPLATE.md`, кнопка **Copy template** в хабе), человек вставляет его в хаб и сразу видит превью.

Наши «родные» движки (`editor`, `word`, `coach`, `motion`) остаются как есть: это параметры поверх готовых анимаций.
Все пять движков рендерятся в видео нашими скриптами локально (Claude склеивает сам): `editor`, `word`, `coach` — свои
скрипты, `motion` и `canvas` — `podcast/tools/hub_subs.py`, который запускает собственный код хаба кадр за кадром (§7).

## 2. Формат пресета

```json
{
 "name": "lava-wave",
 "title": "Lava Wave",
 "engine": "canvas",
 "runtime": 1,
 "description": "Одно предложение: как выглядит и когда использовать.",
 "fonts": ["Montserrat:900"],
 "params": [
  { "name": "size",  "label": "Text size",        "min": 0.7, "max": 1.3,  "value": 1 },
  { "name": "y",     "label": "Height on screen", "min": 0.3, "max": 0.85, "value": 0.64 },
  { "name": "color", "label": "Lava colour", "type": "color", "value": "#ff6a00" }
 ],
 "code": ["const P = s.phraseAt(s.t, { maxWords: 3 });", "if (!P) return;", "..."]
}
```

| Поле | Что это |
|---|---|
| `name` | id для чата и базы: латиница, цифры, дефисы (`use subs lava-wave`) |
| `engine` | всегда `"canvas"` |
| `runtime` | версия API `s` (см. §4), под которую написан код. Сейчас `1` |
| `fonts` | Google Fonts: `"Family"` или `"Family:400,800"`, курсив `"800i"`, до 6 штук |
| `params` | базовые ползунки (до 8, лишние отбрасываются с предупреждением): число `{name,label,min,max,value[,step]}` или цвет `{name,label,type:"color",value:"#rrggbb"}`. `name` — слово для кода (`^[a-z][A-Za-z0-9_]{0,30}$`, до 31 символа) |
| `code` | тело функции `function (ctx, s) { ... }`. Массив строк (читается и диффается) или одна строка — платформа склеивает через `\n`. До 60 000 символов |

Где лежит: база артефакта, `sublib/<name>` (библиотека владельца) и `subs/<uid>/items/<name>` (у каждого автора своё).
Формат статически проверяет `validatePreset()` (ветка `canvas`), при публикации — ещё и прогоном (§6).

## 3. Контракт выполнения

- Платформа на каждый кадр вызывает `code(ctx, s)`.
- `ctx` — `CanvasRenderingContext2D`, уже отмасштабированный в координаты кадра `s.W × s.H`, очищенный, **прозрачный**.
  Код рисует только сабы; видео лежит снизу.
- **Форматы:** команда выпускает два кадра — **9:16 (1080×1920)** и **16:9 (1920×1080)**; хаб показывает превью в обоих.
  Код не должен зашивать 1080/1920: раскладка от `s.W`, `s.H`, `s.safe`, длины × `Math.min(s.W, s.H) / 1080`.
- **Детерминизм:** картинка зависит только от `s.t` (+ слова, размер, ползунки). Время может прыгать назад
  (превью зациклено, экспорт идёт кадр за кадром). Никаких `Math.random()`/`Date` — для этого `s.rand`/`s.noise`.
  Состояние между кадрами — только кэши в `s.memo` (сбрасывается при смене текста, формата или ползунка).
- **Песочница:** у кода нет сети, DOM платформы, картинок. Только Canvas 2D (пути, градиенты, текст, `ctx.filter`,
  `getImageData`/`putImageData` на служебных слоях).
- **Скорость:** в превью хаба (640 px по длинной стороне) — единицы мс на кадр. Lava Wave: ~3 мс (9:16) и ~1.3 мс
  (16:9) на 640 px; ~50 мс/кадр в headless Chromium без GPU на полном 1080×1920.

## 4. API `s` (runtime 1)

| | |
|---|---|
| `s.t` | время кадра, сек |
| `s.W`, `s.H` | размер кадра: 1080×1920 (9:16) или 1920×1080 (16:9); рантайм принимает любой |
| `s.safe` | `{x0,y0,x1,y1}` — безопасная зона: по бокам `0.065·W`, сверху `0.1·H`, снизу `0.17·H` для вертикали (H/W > 1.5), иначе `0.08·H` |
| `s.params` | значения ползунков по `name` (читать с запасным значением) |
| `s.words` | `[{text, start, end}]` — слова с таймингами (сек от начала ролика), текст как сказан, с пунктуацией |
| `s.total` | длина ролика, сек |
| `s.phrases(opt)` | разбивка слов на экранные фразы `[{a,b,idx,start,end,from,to}]`; `opt = {maxWords:6, maxChars:30, maxDur:2.8, gap:0.35, lead:0.1, hold:0.4}`; режет по концу предложения и паузам ≥ gap; фраза на экране с `from` до `to` |
| `s.phraseAt(t, opt)` | фраза на экране в момент t или `null` |
| `s.wordAt(t)` | индекс произносимого слова (последнее с `start <= t`), `-1` до первого |
| `s.prog(t,t0,dur)`, `s.clamp`, `s.lerp` | прогресс 0..1, ограничение, интерполяция |
| `s.ease.*`, `s.bezier(x1,y1,x2,y2)` | linear, in/out/inOut Quad/Cubic, outQuart, outExpo, inOutSine, outBack; CSS cubic-bezier |
| `s.measure(text, font)` | ширина текста, px |
| `s.layer(id)` | очищенный offscreen-слой в тех же координатах |
| `s.blit(layer, {alpha, blur, color, blend})` | наложить слой (blur в px, color — тонировка, blend — `globalCompositeOperation`) |
| `s.glow(fn, opts)` | нарисовать фигуры в слой, затонировать, размыть, наложить |
| `s.noise(x, seed)`, `s.rand(n)` | гладкий шум −1..1, детерминированное «случайное» 0..1 |
| `s.k` | масштаб «пиксель кадра → пиксель устройства» |
| `s.memo` | кэш между кадрами |

Реализация — функция `canvasRuntime()` в `skillhub/index.html`, без зависимостей.

**Версии.** Добавлять в `s` новое можно в рамках runtime 1. Если что-то меняется несовместимо, это runtime 2,
а платформа держит прослойку для пресетов с `"runtime": 1`. Хаб предупреждает, если пресет написан под версию новее,
чем он умеет.

## 5. Как это крутится в хабе (превью)

1. Для каждой карточки / окна превью создаётся `<iframe sandbox="allow-scripts" srcdoc=...>` — непрозрачный origin:
   у кода пресета нет доступа к хабу, его базе и аккаунту зрителя. **Изоляция по процессам зависит от браузера.**
   Chrome на десктопе (и приложение Claude) выносит sandbox-iframe в отдельный процесс от хаба, но **все** превью
   хаба делят один такой процесс: зависший пресет на это время останавливает остальные canvas-превью и проверку.
   Поэтому в хабе есть сторож: превью, не ответившее 2.5 с, удаляется, карточка пишет «The code stopped answering»
   (так же — превью, которое шлёт больше 400 сообщений в секунду). Без такой изоляции (Safari, Firefox, headless
   Chromium по умолчанию) зависший код подвешивает всю страницу. **В Kaleido:** выполнять код пресета в Worker
   (OffscreenCanvas) или в отдельном процессе с лимитом времени на кадр, а в сетке не крутить чужой код всем подряд
   (постер-кадр, живое превью — только у открытого пресета).
2. Превью перестраивает iframe только когда код или шрифты действительно сменились: снимок кода берётся при
   обновлении превью (с задержкой 0.35 с после ввода), а не на каждый кадр. Сетка сабов не пересоздаёт карточки при
   поиске и фильтрах — только прячет (перестройка iframe = перезагрузка и мигание). Под открытым окном пресета или
   редактором карточки сетки не анимируются.
3. `srcdoc` = `<link>` на Google Fonts + рантайм (`canvasRuntime`) + `window.__draw = function (ctx, s) { <code> }`
   (`canvasDoc()`).
4. Родитель шлёт `postMessage`:
   - `{hubCanvasIn: 1, words, total, W, H, params}` — при старте и при смене текста / формата / ползунков;
   - `{hubCanvasIn: 1, t}` — на каждый кадр;
   - `{hubCanvasIn: 1, check: {...}}` — прогон проверки (§6).
   Ответы: `{hubCanvas: 1, alive: 1}` не чаще раза в 200 мс после отрисовки (для сторожа).
5. Iframe отвечает `{hubCanvas: 1, ready: 1}`, `{hubCanvas: 1, err: "..."}` (ошибки кода показываются на превью)
   и `{hubCanvas: 1, check: {...}}` (только числа, пиксели наружу не уходят).
6. Фон (тёмный / светлый / свой кадр) рисует родитель под прозрачным iframe.
7. **Формат 9:16 / 16:9** переключается только в окне конкретного пресета (карточка и редактор); окно превью
   остаётся 9:16, кадр 16:9 показывается полосой по центру с серыми полями сверху и снизу. Выбор запоминается у зрителя (`localStorage hub.fmt`), отдельно
   для сабов и для переходов. Сетка карточек всегда вертикальная.

## 6. Проверка при публикации

**Canvas-сабы** (`runCanvasCheck()` + `runCheck()` в рантайме). Пока код/шрифты/ползунки в редакторе меняются,
хаб (через 0.45 с после последнего изменения) поднимает отдельный скрытый sandbox-iframe и прогоняет код на тестовом
тексте: 48 кадров по всему ролику в 9:16 и в 16:9, холст 640 px по длинной стороне, между кадрами — уступка потоку
(MessageChannel), пиксели анализируются на копии в 1/4 размера. Кнопка Publish ждёт результат («Checking…»).
Значения ползунков снимаются один раз на старте прогона; результат принимается, только если подпись
(код + шрифты + ползунки) совпадает с текущей.

Протокол: хаб шлёт `{hubCanvasIn: 1, check: {id, words, total, params, size: 640, frames: 48, formats: [[1080,1920],[1920,1080]]}}`,
рантайм отвечает `{hubCanvas: 1, check: {checkId, formats: [{W, H, n, errors, errorFrames, speaking, emptySpeaking,
edgeFrames, belowFrames, nondet, avgMs, p95Ms, maxMs}], fatal?}}`.

| Блокирует публикацию | Предупреждение |
|---|---|
| код не загрузился (синтаксис) | 12+ мс/кадр в среднем или 25+ мс у медленных — «тяжёлый» |
| исключение хотя бы в одном кадре | пустые кадры, пока звучит слово (не больше половины таких кадров) |
| нет ответа за 10 с — зависание | сплошная заливка (альфа > 128) у края кадра в 10%+ кадров (обрезано?) |
| пусто больше чем в половине кадров, где звучит слово | 9:16: заливка в нижней полосе под кнопками приложения в 10%+ кадров |
| 50+ мс/кадр в среднем на 640 px или один кадр дольше 1 с | кадр, нарисованный повторно вне очереди, отличается (состояние между кадрами) |

«Пустой» кадр — меньше 3 пикселей с альфой > 10 на копии 1/4 (≈ 48 на 640 px). Сравнение «повторно вне очереди» идёт
по сетке 24×24 средних (альфа × яркость) с допуском 4 уровня — разница округления размытия GPU/CPU не считается,
`Math.random()` и счётчики в `s.memo` ловятся. Проверка — фильтр качества, не граница доверия: код пресета живёт в
том же окне, что и рантайм проверки, и теоретически может подделать ответ; доверять ему всё равно нельзя (§8).

**Переходы** (`transCheck()`). На общем WebGL2-контексте, по тестовым кадрам 90×160 и 160×90: при progress 0
шейдер обязан показать A, при 1 — B (допуск 6 уровней максимум, 0.6 в среднем) — иначе Publish заблокирован;
если середина (0.25/0.5/0.75) целиком чёрная — предупреждение (NaN). Результат кэшируется по шейдеру, настройкам и
длине; в редакторе проверка запускается через 0.3 с после последнего движения ползунка (не на каждый шаг), сразу —
по «Compile and play». Все 10 переходов библиотеки проходят; негативные тесты (смесь 50/50, чёрная середина,
синтаксис) ловятся.

## 7. Экспорт в видео

Превью в хабе — это живой браузер поверх тестового фона. В рекламе сабы должны быть **впечатаны в кадры mp4**.
Раз код — детерминированная функция времени, экспорт простой:

```
для кадра n = 0 .. N-1:
    t = n / fps
    очистить холст W×H (прозрачный), вызвать code(ctx, s) с s.t = t
    взять RGBA кадра  ->  наложить поверх кадра n видео  (или собрать в поток с альфой)
```

**Уже работает локально:** `podcast/tools/hub_subs.py --style <preset.json> --words <words.json> --video <in.mp4> --out <out.mp4>`
(`--param name=value`, `--offset`, `--preview N`). Motion: страница хаба в headless Chromium, `attachView` + `drawSubFrame` на
прозрачном холсте 1080×1920 (только 9:16). Canvas: тот же защищённый рантайм, что в `tools/preview.py` (песочница, сеть закрыта),
кадр 1080×1920 или 1920×1080 по форме видео. Кадры RGBA сразу идут в ffmpeg и накладываются на видео, звук копируется,
NVENC ~5 Мбит/с. Скорость: Motion ~20 кадров/с, Lava Wave ~3.5 кадра/с (ролик 30 с ≈ 4–5 мин). Браузер — в дочернем процессе;
нет прогресса `--timeout` секунд — дерево процессов убивается. Девам Kaleido это нужно, только если рендер будет на их сервере.

Варианты:
- **Сервер:** headless Chromium (Playwright/Puppeteer) грузит тот же `srcdoc` на нативном W×H, по кадру делает
  снимок с прозрачным фоном (или отдаёт `getImageData`), ffmpeg накладывает на видео / собирает ProRes 4444,
  VP9-alpha или PNG-последовательность.
- **В браузере пользователя:** тот же рантайм на `OffscreenCanvas` + WebCodecs.

Рабочий прототип покадрового рендера — `skillhub/tools/preview.py` + `build_page.js`: тот же рантайм (берётся прямо
из `skillhub/index.html`), тот же код, рендер по кадрам в 9:16 или 16:9 с любыми значениями ползунков:

```
python skillhub/tools/preview.py <preset.json> <out_dir> --fmt 16:9 --param color=#00a8ff --param size=1.2 [--shots 1.2,3.4] [--timeout 20]
```

Прототип сделан так, как должен работать экспорт: код пресета живёт в `<iframe sandbox="allow-scripts">` с CSP
(`default-src 'none'`, шрифты только с Google Fonts) внутри хост-страницы; сеть браузера закрыта (Playwright route
пропускает только саму страницу и fonts.googleapis.com / fonts.gstatic.com, плюс DNS-правило и запрет UDP у WebRTC);
браузер работает в дочернем процессе (на Windows — в job object), и если загрузка, шрифты или один кадр не
продвигаются `--timeout` секунд, всё дерево процессов убивается, а в `errors.txt` пишется «the preset hangs or is far
too slow at t=…». Время на кадр печатается двумя числами: JS-отрисовка (как в проверке хаба) и полный цикл с
отрисовкой браузером. CSP запрещает `eval`/`new Function` — такой пресет в прототипе упадёт.

Что нужно на входе экспорта:
- **Слова с таймингами** `[{text, start, end}]` от начала ролика. У нас их дают Groq Whisper, ElevenLabs Scribe,
  точные начала слов — wav2vec2. Качество синхрона = качество этих таймингов.
- **Шрифты** из `fonts` (скачать из Google Fonts в окружение рендера).
- **fps и размер кадра** ролика (`s.W`, `s.H`).
- Значения ползунков пользователя.

Переходы уже рендерятся в видео: `podcast/tools/transitions.py` — тот же GLSL в moderngl на GPU, любой размер кадра.

## 8. Безопасность

Код пресета — недоверенный: опубликовать может любой. Выполнять **только изолированно**:
- в браузере: iframe `sandbox="allow-scripts"` без `allow-same-origin` (так в хабе);
- на сервере: отдельный процесс браузера без доступа к внутренним сервисам, сеть закрыта (кроме шрифтов),
  **лимит времени на кадр** и на весь рендер (зависший пресет не должен держать очередь) — как в `tools/preview.py`.
- в превью хаба сеть ограничивает CSP самой страницы claude.ai (srcdoc-iframe её наследует); локально (localhost)
  такого ограничения нет.

## 9. Шаблон для Claude и цикл качества

- `CANVAS_TEMPLATE.md` (и кнопка **Copy template** в хабе) — инструкция для любого Claude без контекста: формат,
  API, правила, планка качества и рабочий пример (Lava Wave).
- Главный вывод тестов: вслепую по шаблону выходит средне, сильно — когда смотрят кадры и правят. Поэтому
  цикл всегда такой: Claude пишет JSON → вставка → Apply → проверка (§6) → смотреть превью на тёмном / светлом в 9:16
  и 16:9 → замечания обратно Claude. Если Claude умеет запускать код, `tools/preview.py` даёт ему кадры сам.

## 11. Открытые вопросы

- Свои файлы шрифтов (не Google) для Canvas-пресетов пока не поддерживаются.
- Нет пословных пометок (ключевое слово, акцент) — можно добавить в `s.words[i]` как runtime 1 без поломок.
- `ctx.filter` (размытие для свечения) — проверить в Safari, на котором будет смотреть команда.
